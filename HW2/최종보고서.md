## 문제 2. BST delete (1, 2, 5, 8, 9)

### 2-1. 해답 — 단계별 도식

문제 1의 최종 BST에서 시작한다. `bintrees.BinaryTree.remove()`는 두 자식이 있는 노드 삭제 시 **in-order successor**(우측 서브트리의 최솟값)로 대체한다.

```
[시작] 문제 1 최종                  [Step 1] delete 1 (leaf)
        5                                   5
       / \                                 / \
      3   7                               3   7
     /     \                             /     \
    2       8                           2       8
   /         \                                   \
  1           9                                   9

[Step 2] delete 2 (leaf)     [Step 3] delete 5 (root, 두 자식)
    5                            7              ← 5를 in-order successor 7로 교체
   / \                          / \
  3   7                        3   8
       \                            \
        8                            9
         \
          9

[Step 4] delete 8 (자식 1개) [Step 5] delete 9 (leaf) — 최종
    7                              7
   / \                            /
  3   9                          3
```

### 2-2. 핵심 기능 요약

- BST 삭제는 노드의 자식 수에 따라 세 가지 경우로 나뉜다.
  1. 자식 없음(leaf): 단순 제거.
  2. 자식 1개: 자식을 노드 위치로 끌어올림.
  3. 자식 2개: in-order successor와 키를 교체하고 successor를 재귀적으로 삭제.
- `bintrees`는 in-order successor 방식을 사용한다.

### 2-3. 출제 의도

- 자식 수에 따른 삭제 케이스 분기를 직접 추적.
- 루트 삭제(5번 단계)에서 successor 치환 과정을 이해.
- 동일 삭제 시퀀스를 AVL에 적용했을 때(4번 문제)와 비교할 기준 마련.

## 문제 3. AVL insert (5, 3, 7, 8, 2, 9, 1)

### 3-1. 해답 — 단계별 도식 (BF = balance factor = height(L) − height(R))

```
[Step 1] insert 5            [Step 2] insert 3            [Step 3] insert 7
    5 (BF=0)                       5 (BF=1)                       5 (BF=0)
                                  /                              / \
                                 3                              3   7

[Step 4] insert 8                              [Step 5] insert 9 → BF(7)=-2 (RR)
    5 (BF=-1)                                       5 (BF=-2)
   / \                                              / \
  3   7 (BF=-1)                                    3   7 (BF=-2)
       \                                                \
        8                                                8
                                                          \
                                                           9
            ↓ left-rotate(7)
[Step 5 after rotation]
    5 (BF=-1)
   / \
  3   8 (BF=0)
     / \
    7   9

[Step 6] insert 2            [Step 7] insert 1 → BF(3)=2 (LL case)
       5 (BF=0)                       5 (BF=1)
      / \                            / \
     3   8                          3   8        (BF(3)=2, BF(2)=1)
    /   / \                        /   / \
   2   7   9                      2   7   9
                                 /
                                1
                                          ↓ right-rotate(3)
[Step 7 after rotation] — 최종 AVL
       5
      / \
     /   \
    2     8
   / \   / \
  1   3 7   9
```

### 3-2. 핵심 기능 요약

- AVL 트리는 모든 노드의 BF가 `{-1, 0, +1}` 범위가 되도록 회전을 통해 균형을 유지하는 BST다.
- 4가지 회전 케이스: LL(우회전), RR(좌회전), LR(좌-우 이중), RL(우-좌 이중).
- 본 시퀀스에서는 두 번의 단일 회전이 발생한다.
  - Step 5: 노드 7에서 RR → 좌회전
  - Step 7: 노드 3에서 LL → 우회전

### 3-3. 출제 의도

- BST 삽입에 회전 보정이 결합된 AVL 알고리즘 이해.
- 동일 입력에 대해 BST vs AVL이 어떻게 다른 모양을 만드는지 비교.
- LL과 RR 두 케이스를 한 시퀀스에서 경험.

### 3-4. 입력 프롬프트 (두 AI)

**Claude 자체 부여 sub-prompt**:

```
빈 AVL 트리에 다음 키를 순서대로 삽입한다: (5, 3, 7, 8, 2, 9, 1)

최종 트리의 세 가지 순회 결과도 출력하라.
```

**GPT-5.5 Codex 자체 부여 sub-prompt**:


## 문제 4. AVL delete (1, 2, 5, 8, 9)

### 4-1. 해답 — 단계별 도식

문제 3의 최종 AVL에서 시작한다. 삭제 후 BF가 깨지면 가까운 조상에서 회전 보정을 수행한다.

```
[시작] 문제 3 최종                  [Step 1] delete 1 (leaf)
       5                                   5
      / \                                 / \
     /   \                               /   \
    2     8                             2     8        (BF(2)=-1, BF(5)=0, BF(8)=0, OK)
   / \   / \                              \   / \
  1   3 7   9                              3 7   9

[Step 2] delete 2 (자식 1개) [Step 3] delete 5 (root, 두 자식)
       5                          7              ← in-order successor 7로 교체
      / \                        / \
     3   8                      3   8
        / \                          \
       7   9                          9

   Step 2 직후 BF: BF(3)=0, BF(8)=0, BF(5)=-1 — 회전 불필요.
   Step 3 직후 BF: BF(8)=-1, BF(7)=-1 — 회전 불필요.

[Step 4] delete 8 (자식 1개) [Step 5] delete 9 (leaf) — 최종
       7                          7
      / \                        /
     3   9                      3

   Step 4 직후 BF: BF(7)=0 — 회전 불필요.
   Step 5 직후 BF: BF(7)=1 — 회전 불필요.
```

### 4-2. 핵심 기능 요약

- AVL 삭제는 BST 삭제와 동일한 케이스 분기를 수행한 뒤, 영향받은 경로의 BF를 점검하여 필요 시 회전한다.
- 본 시퀀스에서는 삭제 직후 모든 노드의 BF가 `{-1, 0, +1}` 범위를 유지하므로 별도의 회전이 발생하지 않는다.
- 최종 트리의 모양·키 집합이 문제 2(BST 삭제 결과)와 동일하다.

### 4-3. 출제 의도

- 삭제에서도 회전이 필요할 수 있음을 알리되, 이번에는 회전이 일어나지 않는 경계 케이스를 경험.
- BST 삭제 vs AVL 삭제의 알고리즘적 차이를 명시적으로 비교.

## 문제 5. Python `bintrees`로 검증

### 5-1. 해답 — 소스 코드 `index.py`

> 본 보고서 루트에 `index.py` 와 `실행결과.txt` 사본을 두었다. 두 AI 산출물(원본)은 `AI_산출물/homework by Claude/`, `AI_산출물/homework by GPT/` 에 보존되어 있다.

```python
from bintrees import BinaryTree, AVLTree

INSERT_SEQ = [5, 3, 7, 8, 2, 9, 1]
DELETE_SEQ = [1, 2, 5, 8, 9]


def collect(tree, order):
    # order: -1=pre, 0=in, +1=post (bintrees foreach 규약)
    out = []
    tree.foreach(lambda k, v: out.append(k), order)
    return out


def show(label, tree):
    print(label)
    print(f"In-order   {' '.join(str(k) for k in collect(tree, 0))}")
    print(f"Pre-order  {' '.join(str(k) for k in collect(tree, -1))}")
    print(f"Post-order {' '.join(str(k) for k in collect(tree, 1))}")
    print()


def build(tree_cls, insert_seq):
    tree = tree_cls()
    for k in insert_seq:
        tree.insert(k, None)
    return tree


def delete_all(tree, delete_seq):
    for k in delete_seq:
        tree.remove(k)
    return tree


def main():
    print(f"Insert sequence: {INSERT_SEQ}")
    print(f"Delete sequence: {DELETE_SEQ}")
    print("=" * 50)

    bst = build(BinaryTree, INSERT_SEQ)
    show("1. BST insert (5,3,7,8,2,9,1)", bst)

    delete_all(bst, DELETE_SEQ)
    show("2. BST after delete (1,2,5,8,9)", bst)

    avl = build(AVLTree, INSERT_SEQ)
    show("3. AVL insert (5,3,7,8,2,9,1)", avl)

    delete_all(avl, DELETE_SEQ)
    show("4. AVL after delete (1,2,5,8,9)", avl)


if __name__ == "__main__":
    main()
```

### 5-3. 핵심 기능 요약

- `bintrees.BinaryTree`: 평형 보정 없는 일반 BST.
- `bintrees.AVLTree`: 회전 기반 자가균형 BST.
- 공통 API: `insert(key, value)`, `remove(key)`, `foreach(func, order)`.
- `foreach(order=-1|0|+1)` 이 pre/in/post-order 순회를 제공해 손계산 결과와 직접 비교 가능.

### 5-4. 출제 의도

- 알고리즘 이론(손계산) ↔ 라이브러리 실측(프로그램) 두 경로의 결과를 교차 검증.
- Python 패키지 설치·사용 능력 점검 (pip + venv 흐름).

**Claude 자체 부여 sub-prompt**:

```

2. 위 트리에서 (1, 2, 5, 8, 9)를 차례로 삭제.
3. 새 AVLTree에 (5, 3, 7, 8, 2, 9, 1)을 차례로 삽입.
4. 위 AVL에서 (1, 2, 5, 8, 9)를 차례로 삭제.
각 단계 끝 트리의 in-order, pre-order, post-order 순회 결과를 출력하라.
```

**GPT-5.5 Codex 자체 부여 sub-prompt**:

```
Python 의 bintrees 패키지를 사용해서 BinaryTree 와 AVLTree 를 만들고,

```

### 5-6. 두 AI 결과 (요약)

- 양쪽 모두 동일한 12개 순회 결과를 출력.
- 코드 스타일: Claude는 `collect/show/build/delete_all` 분리, GPT는 `traversal/print_traversals` 분리. 출력 형식만 약간 다름 (라벨/헤더 위치 등).

## 7. 통합 결과 분석

### 7-1. 문제 1 — BST insert

- In-order 순회가 정렬된 수열을 출력 → BST 불변식(좌소우대) 유지 확인.
- 트리 높이 4. 좌·우로 각각 한 갈래씩 길게 뻗어 균형이 흐트러진 모양.
- 입력 시퀀스의 부분 정렬성 때문에 자연스럽게 비균형이 발생.

### 7-2. 문제 2 — BST delete

- 루트 삭제(5번 단계)에서 우측 서브트리의 최솟값 7이 successor로 선택되어 루트로 올라간다.
- 7이 원래 위치에서 사라진 자리는 자식 8이 그대로 위로 끌어올려 채운다.
- 최종 트리는 BST 정의를 그대로 유지 (3 < 7).

### 7-3. 문제 3 — AVL insert

- 같은 입력에 대해 AVL은 완전이진트리에 가까운 균형 트리를 만든다.
- 회전은 부분 트리만 재배치하므로 in-order 결과는 변하지 않는다 (BST 정렬 유지).
- 트리 높이가 BST의 4 → AVL의 3으로 줄어든다. 탐색 비용 측면에서 직접적 이득.

### 7-4. 문제 4 — AVL delete

- 본 시퀀스는 작은 입력 + 균형 잡힌 시작 트리 덕분에 삭제 후에도 BF가 깨지지 않았다.
- 만약 삭제 후 BF가 ±2였다면 LL/RR/LR/RL 중 하나의 회전이 필요했을 것이다.
- 최종 결과가 문제 2와 동일하다는 점은 "AVL은 회전이 필요 없는 한 BST와 같은 결과를 만든다"는 일반 성질을 보여준다.

### 7-5. 문제 5 — bintrees 검증

- BST의 1번과 AVL의 3번이 같은 in-order(`1 2 3 5 7 8 9`)를 출력 → BST 불변식은 동일, 트리 모양(pre/post-order)은 상이. **AVL 회전이 모양만 바꾸고 정렬 순서는 보존**한다는 사실의 명시적 증거.
- 2번과 4번 결과가 동일 → 본 시퀀스에서 AVL 삭제 시 회전이 발생하지 않았기 때문.
- `bintrees`의 두 자식 삭제 규약(in-order successor)이 강의 자료와 일치하므로, 강의 도식과 라이브러리 결과가 호환된다.

### 7-6. 통합 결론

- 손계산 12개 항목 vs 두 AI 산출물 vs `bintrees` 프로그램 출력의 3자 비교 결과 모두 일치 (§6 표 참조).
- BST와 AVL의 차이는 "결과 정렬은 동일, 트리 모양·높이는 상이"로 요약된다.
- AVL이 항상 회전을 수반하는 것은 아니라는 점(문제 4)이 학습 측면에서 중요한 포인트.
