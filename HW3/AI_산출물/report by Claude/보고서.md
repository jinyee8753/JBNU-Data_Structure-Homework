## 1. 해답 — 구현 요약

guide code 골격(함수 6개 + `data_files` 루프 + `open("./{0}".format(f))` / `readlines` / `close`)을 유지하고 TODO만 채웠다.

| 함수 | 방식 | 복잡도 |
| --- | --- | --- |
| `insertion_sort` | key를 왼쪽 정렬 구간에 삽입, 원소 우측 이동 | 평균/최악 O(n²), 최선 O(n) |
| `selection_sort` | 미정렬 구간 최솟값 탐색 후 앞과 교환 | 항상 O(n²) |
| `heap_sort` | bottom-up build-heap(max-heap) + sift-down, in-place | O(n log n) |
| `merge_sort` | top-down 분할, 보조 배열 병합, 입력 리스트에 다시 기록 | O(n log n) |
| `quick_sort` | Lomuto partition + 마지막 원소 pivot, in-place. 작은 쪽 먼저 재귀(깊이 ≤ log₂n) | 평균 O(n log n), 최악 O(n²) |
| `built_in_sort` | `list.sort()` (Timsort, C 구현) | O(n log n) |

측정 프로토콜:

- 알고리즘마다 원본의 **fresh copy**를 정렬 (정렬된 입력 재사용 시 insertion sort가 O(n)으로 왜곡).
- `time.perf_counter()`로 **정렬 함수 실행만** 측정 — 파일 I/O·int 변환·copy 생성·assert는 타이머 밖.
- 셀당 1회 측정. 모든 결과를 `expected = sorted(원본)`과 assert 비교 (6×5=30셀 전수 검증).
- numpy 사용처: `np.array(..., dtype=np.int64)` 데이터 변환, 결과 배열 처리(`np.array`) 및 포맷.

## 4. 결과 분석

**O(n²) 성장률 검증** — n이 2배(500→1K)일 때 selection 4.2배, insertion 4.5배 (이론값 4배). n이 10배(10K→100K)일 때 selection 107배, insertion 116배 (이론값 100배). 점근 분석과 실측이 일치한다.

**insertion vs selection** — 100K에서 insertion(151.7초)이 selection(104.7초)보다 1.45배 느리다. selection은 비교 위주(교환 최대 n-1회)인 반면 insertion은 무작위 입력에서 평균 n²/4회의 원소 이동(리스트 쓰기)을 수행하므로, Python 인터프리터에서 쓰기 연산 비용이 더해진 결과다.

**O(n log n) 3종 비교** — 100K 기준 quick(92.7ms) < merge(147.7ms) < heap(200.4ms). quick은 partition 단일 루프의 순차 접근(캐시 친화), merge는 보조 배열 복사 오버헤드, heap은 sift-down의 비순차 메모리 접근과 비교 횟수가 비용 요인이다.

**built-in과의 격차** — python list.sort()(Timsort, C 구현)는 100K에서 9.51ms로 quick보다 약 10배, selection보다 약 11,000배 빠르다. 같은 O(n log n)이라도 인터프리터 루프와 C 구현의 상수항 차이가 압도적임을 보여준다.

**O(n²) vs O(n log n) 격차** — 100K에서 selection/heap = 523배, insertion/quick = 1,636배. 500에서는 약 5~14배에 불과하던 격차가 n 증가에 따라 폭발적으로 벌어진다.

## 6. 출제 의도 (Claude 해석)

- O(n²) 와 O(n log n) 의 점근 차이를 실측으로 체감시키고 (100K에서 수백~수천 배), 같은 O(n log n) 이라도 상수항·메모리 접근 패턴·구현 언어에 따라 실측이 달라짐을 인식시키는 과제다.
- in-place 개념 (partition / sift-down) 과 merge 의 보조 배열 비용, 그리고 공정한 측정 방법론 (fresh copy, 측정 범위 격리) 설계 경험도 함께 요구한다.
